## 2023-09-17 - Insecure Directory Permissions for Keystore/Config
**Vulnerability:** The application's sensitive directory (`.x402wallet`), which stores keystores and config files, was being created using the default `std::fs::create_dir_all`. On Unix systems, this respects the user's `umask`, which often defaults to `022`. This means that by default, other local users on the same machine could read the configuration and encrypted keystore files.
**Learning:** Default filesystem operations are risky when dealing with sensitive wallet files. Relying on default `umask` configurations does not provide a robust security posture against local threats.
**Prevention:** We have introduced a `secure_create_dir_all` helper function in `src/utils.rs` that leverages `std::os::unix::fs::DirBuilderExt` to explicitly set `0o700` restricted permissions (owner read/write/execute only). Any code attempting to create storage paths for sensitive data MUST use this helper function instead of standard `fs` directory creation primitives.
